1. Откройте нужную ссылку из таблицы ниже под своим аккаунтом `Shalygin1`.
2. Нажмите карандаш **Edit this file**. Если карандаш спрятан, откройте меню `…` файла и выберите **Edit file**.
3. Меняйте только текст в кавычках. Сохраняйте имена ключей, кавычки, запятые, HTML-теги и подстановки вроде `{date}`. Для апострофа внутри строки используйте `\'` либо двойные кавычки вокруг всей строки.
4. Нажмите **Commit changes**, укажите короткое описание и сохраните изменение непосредственно в ветке `main`.
5. GitHub Pages автоматически публикует содержимое `main`, папку `/ (root)`. Отдельной сборки после правки текста не требуется. Дождитесь зелёного результата **pages build and deployment** во вкладке **Actions**, затем обновите сайт с очисткой кэша: Cmd+Shift+R.
6. Для проверки используйте адрес сайта с `?test=1`: такие результаты направляются в отдельную папку TEST. Участникам отправляйте обычную ссылку без `test`.

## Последовательность одной пробы

Видео полностью загружается до начала предъявления. Затем — отдельный серый экран с крестом на **600 мс**, автоматическое воспроизведение, первый ответ, досмотр и отдельная кнопка **«Далее»**. Эта последовательность одинакова в тренировке и основном блоке. Кнопки «Начать видео» нет. Редкое исключение — кнопка разрешения воспроизведения, если сам браузер запретил автозапуск, либо продолжения после системной паузы.

RT считается от первого отображаемого кадра (`requestVideoFrameCallback`; запасной метод — `playing`) до первого ответа. Предварительная загрузка, фиксация и ожидание нажатия «Далее» в RT не входят. При раннем ответе обе кнопки блокируются, видео продолжает идти. «Далее» доступна только после `ended`, ответа и подтверждения сохранения пробы. Перемотка и повторный просмотр не предусмотрены. Пропорции исходника сохранены через `object-fit: contain`; чёрные поля внутри самих записей PEDFE не обрезаются.

Паузы при скрытии вкладки, потеря фокуса, повтор после обновления, ошибки воспроизведения и пропуски кадров помечаются в данных. RT при системной паузе продолжает учитывать реальное прошедшее время; такие пробы проверяются отдельно. Критерии исключения заранее согласуйте в протоколе, а не определяйте по результату участника.

## Данные Google Drive

DataPipe подключён к Google Drive, интеграция с OSF для результатов не используется. Нужный публичный **experiment ID** хранится в настройках; это идентификатор приёма данных, не пароль от Drive. OAuth-токенов и секретов в репозитории нет.

Итог — один уникальный JSON на завершённую сессию: `participant_<UUID>.json`. Тесты используют отдельный приём и файл `TEST_<UUID>.json`. Есть:

- `main_trials`: все 48 отдельных основных проб;
- `practice_trials`: 4 тренировки;
- `manipulation`: ролевое распределение / ознакомление;
- `power_checks`: проверка власти до и после;
- `session`: ID, случайно назначенная группа, порядок, согласие, статус;
- `summary`: `n_correct`, `n_main=48`, `accuracy_percent`;
- `events`: полный журнал подтверждённых исследовательских событий;
- технические поля внутри каждой пробы и `technical_journal`.

Пока идёт прохождение, DataPipe сохраняет промежуточные события, а браузер хранит локальную копию. Незавершённые проходы могут появляться как `.partial.json`; они не считаются завершёнными участниками. При ошибке итоговой отправки экран успеха не показывается: можно повторить тот же неизменённый файл с тем же UUID. Статус 202 означает принятие сервисом в очередь, поэтому повторная отправка не нужна. Отзыв участия передаётся отдельной отметкой `withdrawal_<UUID>.json`; такие UUID исключаются из анализа, а запросы на удаление промежуточных копий исследователи исполняют в Drive.

Для основного анализа берите только завершённые нетестовые сессии: `status=complete`, `is_test=false`, `media_mode=pedfe`, `allow_use_after_debrief=true`, 48 основных проб, согласованная версия процедуры. Сначала исключите UUID с отметкой отзыва. Скачанные файлы, промежуточные копии и резервные копии нужно удалить по окончании срока хранения. Программа закрывает начало новых сессий после указанной даты; автоматическое удаление файлов из Google Drive не настроено.

В JSON поля `media_mode` и `allow_use_after_debrief` находятся внутри `session`. В CSV эти признаки следует присоединять из сессии. В итоговом файле `technical_journal` отдельно сохраняет первый ответ и момент нажатия «Далее»; на RT это нажатие не влияет. Прямые поля `next_clicked_at` в основной строке оставлены пустыми, поскольку строка фиксируется до перехода; используйте соответствующую запись журнала с теми же `phase` и `trial_number`.

После прохождения участник также может скачать CSV с 48 основными строками или полный JSON. Для обработки локально подходят R и Python; Google Sheets не требуется.

## Реальные стимулы и лицензия

Используется прежний отбор seed `20261119`, 24 актёра в genuine/posed парах. В каждой ячейке «эмоция × подлинность» 4 записи, из них 2F/2M. Четыре тренировки не пересекаются с основными актёрами. Манифест содержит оригинальные имена, строки T5, длительности, число кадров и SHA-256.

Реальная таблица — `Supplemental_Material_T5.xlsx`, лист `Foglio1`, заголовки в строке 6. Из 1458 строк доступны 1456 AVI; отсутствуют `30_dg_1.avi` и `5_dg_1.avi`, они не использованы. Все 52 выбранных файла повторно сопоставлены с T5. В исходных 52 записях нет звуковых дорожек. Конвертация в H.264/MP4 не меняет число кадров, не обрезает ролики и не ускоряет их; наибольшее расхождение длительности — менее 10 мс.

[Проверка CC0 и упоминания EULA](docs/HOSTING-LICENSE.md). Исходные AVI, полный массив и XLSX не загружаются в GitHub; публикуются только выбранные 52 веб-копии и их манифест. Результаты участников в GitHub не попадают.

## Локальная версия

Дважды откройте `Запустить эксперимент.command`, затем `http://127.0.0.1:8787`. Если прежний локальный сервер ещё работает, остановите его Ctrl+C в его терминальном окне и запустите заново. Локальный режим использует существующий Node.js-сервер и SQLite, а веб-версия Pages — DataPipe. Исходный репозиторий не требует npm-зависимостей.

```sh
node server/local.mjs
node --test tests/*.test.mjs
```

Все реальные локальные оригиналы и старые результаты сохранены в `private/` и `results/`; обе папки исключены из Git. Повторная подготовка веб-копий при наличии локальных файлов: `node scripts/prepare-pages.mjs`. Это не требуется для обычной правки текста на GitHub.
