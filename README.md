## Как редактировать тексты и публиковать изменения

1. Под аккаунтом `Shalygin1` откройте [файл текстов](https://github.com/Shalygin1/emotion-perception-study/blob/main/web/content/ru.js) и нажмите карандаш **Edit this file** (иногда он находится в меню `…`).
2. Меняйте текст в кавычках. Сохраняйте имена ключей, запятые, кавычки, HTML-теги и подстановки `{date}`, `{contacts}`. Не меняйте `key` трёх вопросов — это имена переменных анализа.
3. Нажмите **Commit changes** и сохраните в ветке `main`.
4. GitHub Pages автоматически публикует `main`, `/ (root)`. Дождитесь завершения **pages build and deployment** во вкладке **Actions**. Обновите страницу через **Cmd+Shift+R**. После обычной правки текста отдельная сборка не требуется.
5. Проверьте через ссылку с `?test=1`. Для выбора тестовой группы допустимы `&condition=high_power` и `&condition=no_power`. В обычном прохождении группа назначается случайно один раз; параметр `condition` без `test=1` не задаёт группу.

## Порядок исследования 0.3

Согласие и один ID → случайное условие → предложение полноэкранного режима → общая инструкция → отдельная ролевая инструкция с визуально выделенными полномочиями → распределение / ознакомление → подтверждение конкретного результата → 4 тренировки → 48 основных проб и прежние перерывы → три финальных вопроса → дебрифинг → добровольное решение об использовании ответов → два CSV и подтверждение.

Предварительного опроса власти нет. Группа высокой власти самостоятельно выбирает `anna_A` или `anna_B` и утверждает обязательное решение. Без власти показывается готовое `anna_A`, доступна только кнопка ознакомления. Задание самого участника остаётся 4+48 при любом распределении.

Три финальных показателя — `perceived_social_power`, `emotion_recognition_ease`, `role_consideration`, каждый целое 1–7. Первый — проверка манипуляции, второй и третий — дополнительные субъективные показатели. Среднее по трём не вычисляется. Они не входят в процент правильных ответов; автоматического исключения по ним нет.

## CSV в Google Drive

DataPipe и прежние закрытые папки сохранены. Новое завершённое прохождение создаёт:

- `trials_<participant_id>_<session_id>.csv`: **ровно 48 строк** основных проб;
- `participant_<participant_id>_<session_id>.csv`: **одна строка** с условием, распределением, тремя ответами, статусом, тестовым признаком и итоговой точностью.

UUID сессии в обоих именах предотвращает перезапись даже при совпадении введённых ID. Тестовые имена начинаются с `TEST_`, и файлы отправляются в отдельную TEST-папку. Кодировка UTF-8 с BOM для Excel, заголовки присутствуют, кавычки/запятые/переносы корректно экранированы. Подробности и все обязательные столбцы: [схема данных](docs/DATA.md).

Сначала отправляются пробы, затем CSV участника — отметка завершения пары. Каждый подтверждённый приём записывается локально. Если второй файл не отправился, повторяется только он, с теми же именем и содержимым. Экран успеха появляется после подтверждения обоих приёмов. HTTP 202 означает принятие сервисом в очередь; повторно отправлять принятый файл не нужно. Для анализа нужны оба файла с одинаковым `session_id`. DataPipe считает отправленные файлы, поэтому два CSV могут увеличить его счётчик на две записи: число участников считайте по уникальным UUID в файлах `participant_…csv`.

Четыре тренировки и технический журнал сохраняются в отдельных столбцах CSV участника как структурированные текстовые значения; события воспроизведения — в столбце `playback_events` каждой пробы. Это сохраняет подробности без добавления тренировочных строк к 48 основным. Необработанные данные не теряются. По окончании участник может скачать оба CSV через две кнопки.

Промежуточная запись DataPipe и локальная копия сохранены. Незавершённые сессии сервис может восстановить как `.partial.json`; это техническое восстановление, а не конечный результат завершённого участника. Завершённые результаты 0.3 — CSV. Прекращение участия записывается отдельной строкой `withdrawal_<session_id>.csv` без ответов. Отозванные UUID исключаются из анализа; по запросу исследователи удаляют уже доставленные промежуточные копии. Ранее собранные файлы 0.2 не удаляются и не переименовываются.

Для основного анализа используйте версию 0.3.0, `is_test=false`, `status=complete`, `allow_use_after_debrief=true`, обе согласованные CSV, 48 проб и отсутствие отметки отзыва. Основной показатель — `n_correct / 48 * 100`. Не смешивайте разные процедуры без отдельного решения. Прежняя сессия в браузере не подхватывается как новая: 0.3 использует отдельный ключ хранения и сохраняет старую запись 0.2.

## Локальная версия и проверка

Запустите `Запустить эксперимент.command`. Если прежний локальный сервер ещё работает, остановите его Ctrl+C в его терминале и запустите заново. Локально данные остаются в SQLite, экспортируются теми же двумя CSV; Pages передаёт их через DataPipe.

```sh
node server/local.mjs
node --test tests/*.test.mjs
```

Исходные AVI, таблица, результаты и служебные файлы остаются в `private/` и `results/`, исключённых из публикации. Для обычной правки текста подготовка видео не нужна.
